### Задание 1 **(2)**
*Переведите в двоичную запись два произвольных рациональных числа (числа вида* $\frac{p}{q}$).
*У одного из чисел знаменатель должен быть степенью двойки (32), а у другого --- некоторым числом
от 9 до 12.*

*Запись второго числа будет содержать период. Его надо найти. При решении задачи нельзя 
использовать вычислительную технику. Процесс решения должен быть представлен в отчете.*

#### Ответ:
**Число 1: $\frac{13}{32}$**

- $\frac{13}{32}$ * 2 = 0 + $\frac{26}{32}$ (0)
- $\frac{26}{32}$ * 2 = 1 + $\frac{20}{32}$ (1)
- $\frac{20}{32}$ * 2 = 1 + $\frac{8}{32}$ (1)
- $\frac{8}{32}$ * 2 = 0 + $\frac{16}{32}$ (0)
- $\frac{16}{32}$ * 2 = 1 + 0 (1)

$\frac{13}{32}$ = $0.01101_2$

**Число 2: $\frac{5}{11}$**

- $\frac{5}{11}$ * 2 = 0 + $\frac{10}{11}$ (0)
- $\frac{10}{11}$ * 2 = 1 + $\frac{9}{11}$ (1)
- $\frac{9}{11}$ * 2 = 1 + $\frac{7}{11}$ (1)
- $\frac{7}{11}$ * 2 = 1 + $\frac{3}{11}$ (1)
- $\frac{3}{11}$ * 2 = 0 + $\frac{6}{11}$ (0)
- $\frac{6}{11}$ * 2 = 1 + $\frac{1}{11}$ (1)
- $\frac{1}{11}$ * 2 = 0 + $\frac{2}{11}$ (0)
- $\frac{2}{11}$ * 2 = 0 + $\frac{4}{11}$ (0)
- $\frac{4}{11}$ * 2 = 0 + $\frac{8}{11}$ (0)
- $\frac{8}{11}$ * 2 = 1 + $\frac{5}{11}$ (1)

$\frac{5}{11}$ = $0.(0111010001)_2$

### Задание 3 **(3)**
*Найдите сумму и произведение для записанных далее пар чисел. Числа заданы в двоичной записи 
в экспоненциальном виде. Ответ необходимо записать в нормализованннои экспоненциальном виде.*

* 1.0011e18 и $1.1001e21;
* 1.1011e-25 и, $1.1101e-23;
* 1.1011e-3 и $1.1011e1.
  
*При решении задачи нельзя 
использовать вычислительную технику. Процесс решения должен быть представлен в отчете.*

#### Ответ:

При сложении выравнить порядки, а при умножении перемножить мантиссы и сложить порядки.

**1) 1,0011 * 2^18 и 1,1001 * 2^21**

Сложение: переносим первое число к порядку 21:

```
  1,1001000 * 2^21
+ 0,0010011 * 2^21
= 1,1011011 * 2^21
```

Произведение мантисс: `1,0011 * 1,1001 = 1,11011011 * 2^1`. Сумма порядков: 18 + 21 = 39.

- **Сумма:** `1,1011011 * 2^21`
- **Произведение:** `1,11011011 * 2^39`

**2) 1,1011 * 2^-25 и 1,1101 * 2^-23**

Сложение: приводим первое число к порядку −23:

```
  1,110100 * 2^-23
+ 0,011011 * 2^-23
= 10,001111 * 2^-23
= 1,0001111 * 2^-22
```

Произведение мантисс: `1,1011 * 1,1101 = 11,00001111₂ = 1,100001111 * 2^1`. Сумма исходных порядков равна −48, поэтому после нормализации порядок равен −47.

- **Сумма:** `1,0001111 * 2^-22`
- **Произведение:** `1,100001111 * 2^-47`

**3) 1,1011 * 2^-3 и 1,1011 * 2^1**

Сложение: приводим первое число к порядку 1:

```
  1,10110000 * 2^1
+ 0,00011011 * 2^1
= 1,11001011 * 2^1
```

Произведение мантисс: `1,1011 * 1,1011 = 10,11011001₂ = 1,011011001 * 2^1`. Сумма исходных порядков −3 + 1 = −2; после нормализации итоговый порядок −1.

- **Сумма:** `1,11001011 * 2^1`
- **Произведение:** `1,011011001 * 2^-1`

### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)
9
```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

#### Ответ:

Python хранит `99.99` как ближайшее доступное двоичное число, а не как точную десятичную дробь. В результате промежуточное значение может оказаться чуть меньше 10. Функция `int()` отбрасывает дробную часть, поэтому получается 9.

Для корректной работы программы нудно заменить `>>> int(x/10+0.001)` на `>>> round(x / 10 + 0.001)`, тогда программы выведет `10`.

### Задание 8 **(2)**

*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

#### Ответ:
Минимальное натуральное число, которое нельзя точно представить в `double`, - **2⁵³ + 1 = 9007199254740993**.

У `double` 53 значащих двоичных разряда с учётом ведущей единицы. Все целые числа до 2⁵³ включительно представимы точно, но около 2⁵³ расстояние между соседними представимыми числами становится равным 2. Поэтому 9007199254740993 находится ровно между двумя доступными числами и округляется к одному из них (при стандартном округлении - к 9007199254740992).

Следующее целое после него, 9007199254740994, уже представимо точно: оно чётное и совпадает с соседним значением сетки `double`. В программе само число следует записывать как целочисленный литерал, а не как литерал с плавающей точкой, иначе округление может произойти ещё при разборе исходного кода.
